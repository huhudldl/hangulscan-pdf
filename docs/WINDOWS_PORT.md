# 한글스캔 PDF — Windows 버전 설계

Mac 버전(`Sources/HangulScan`, Swift)을 Windows로 옮기기 위한 설계 문서입니다.
Windows PC에서 Claude Code로 이 저장소를 열고 **"docs/WINDOWS_PORT.md 대로 Windows 버전을 만들어줘"** 라고 하면 이어서 작업할 수 있도록 정리했습니다.

- Windows 코드는 이 저장소의 `windows/` 폴더에 둡니다 (Mac 코드와 한 저장소).
- Mac 버전의 화면 구성·기능·처리 방식(수치 포함)은 그대로 따르고, **밑바탕 부품만 Windows용으로** 바꿉니다.
- 사용자에게 보이는 글자(메뉴·안내·오류)는 모두 한국어입니다.

## 1. 기술 선택

| 역할 | Mac 버전 | Windows 버전 (추천) | 라이선스 |
|---|---|---|---|
| 언어·화면 | Swift + SwiftUI | **C# / .NET 8 + WPF** | MIT |
| PDF 보기·렌더링 | PDFKit | **PDFium** (`PDFiumCore` 또는 `PdfiumViewer` 계열) | Apache-2.0/BSD |
| PDF 만들기(검색 글자층) | CoreGraphics PDF | **PDFsharp 6** (투명 글자 그리기 가능) | MIT |
| PDF 편집(쪽 순서·삭제·합치기·암호) | PDFKit | **PDFsharp** (암호: `SecuritySettings`) | MIT |
| 한국어 OCR | Vision `VNRecognizeTextRequest` | **Windows.Media.Ocr** (Windows 내장, 기기 안 처리) | OS 내장 |
| 이미지 보정 | CoreImage | **OpenCvSharp4** | Apache-2.0 |
| 문서 영역 감지 | `VNDetectDocumentSegmentationRequest` | OpenCV 윤곽선(가장 큰 사각형) + 밝기 대비 검사 | — |
| 카메라 | AVFoundation | `Windows.Media.Capture` (MediaCapture) | OS 내장 |
| 스캐너 | ImageKit | **WIA** (`WIA.CommonDialog`) | OS 내장 |
| 읽어주기 | AVSpeechSynthesizer | `Windows.Media.SpeechSynthesis` (한국어 음성 '혜미') | OS 내장 |
| 설치 파일 | .app | **Inno Setup** 설치 파일(.exe) 또는 MSIX | — |

**WPF를 고른 이유**: 가장 안정적이고 자료가 많으며, `Windows.Media.Ocr`·음성 같은 Windows API는 `net8.0-windows10.0.19041.0` 대상 설정만으로 바로 쓸 수 있습니다. (WinUI 3도 가능하지만 배포·도구가 더 까다로움)

## 3. 처리 방식 (Mac에서 시험으로 맞춘 값 — 그대로 옮길 것)

좌표: Mac 코드는 정규화 좌표(0~1, **원점 왼쪽 아래**)를 씁니다. Windows OCR은 픽셀·**왼쪽 위 원점**이므로 변환에 주의.

### 3.1 OCR (`OcrEngine`)
- 언어: 한국어 기본 + 영어(설정). Windows OCR은 `OcrEngine.TryCreateFromLanguage(new Language("ko"))`. 한국어 언어 팩이 없으면 "Windows 설정 › 언어에서 한국어 OCR을 설치하세요" 안내.
- Windows OCR은 **이미지 긴 변 최대 `OcrEngine.MaxImageDimension`(보통 10000px)** 제한 → 넘으면 줄여서 인식 후 좌표를 되돌림.
- 결과 줄(`OCRLine`): 글자, 상자, 확신도, 애매한 글자 위치, 다른 후보.
  - Windows OCR은 확신도·후보를 주지 않음 → **"확인 필요" 판단을 바꿔야 함**: 같은 줄을 (a) 원본 (b) 약간 선명화한 이미지로 두 번 인식해 글자가 다르게 나온 곳을 애매한 글자로 표시(Mac의 `ambiguity()` 규칙과 같게: 띄어쓰기 차이·글자 빠짐은 무시, 길이가 같고 1~2글자만 다른 경우만).
- 읽는 순서 정리(`layoutText`): 줄 가운데 높이로 위→아래 정렬, 세로로 절반 이상 겹치면 같은 행으로 묶어 왼쪽→오른쪽.

### 3.2 스캔 보정 파이프라인 (`ImageProcessor.process`)
1. **문서 영역 자르기**: 긴 변 1024px로 줄여 사각형 감지 → 넓이 0.12~0.95, **종이(안쪽) 평균 밝기 − 바깥 평균 ≥ 0.12**(책 모드 0.05)일 때만 원근 보정. 네 꼭짓점을 중심 쪽으로 **1.2%** 들여서 자름(배경 한 줄 남는 것 방지).
2. **방향 + 기울기 (OCR 한 번으로)**: 긴 변 1600px 이미지 OCR →
   - 글줄 각도(줄 상자 아래변 방향)의 **길이 가중 중앙값**이 |45°| 초과면 90° 단위로 돌림: `turn = -round(각도/90)*90`.
   - 아니고 인식 점수(확신도×글자 수 합) < 80이면 180° 돌린 이미지로 다시 인식해 점수가 1.5배+10보다 크면 180°.
   - 기울기 = 회전 반영한 글줄 각도(|각도|<30°)들의 가중 중앙값.
   - **투영 분석으로 정밀화**: 회색조 1000px, 글자 영역 안의 어두운 픽셀(평균 밝기×0.7, 40~170 사이)을 각도별 가로 투영해 (행 합계²)의 합이 최대인 각도. 글줄 추정치 ±2°를 0.25° 간격 → ±0.3°를 0.05° 간격. 글줄 추정과 1° 넘게 다르면 글줄 값을 씀. 글줄이 없으면 ±15°를 0.5° 간격으로 찾고, 0°보다 5% 이상 좋을 때만 채택.
   - 0.1° ≤ |기울기| ≤ 25° 일 때만 회전. **회전 후 빈 모서리는 이미지 테두리 2% 띠의 중앙값 색**으로 채움(흰색 고정 아님 — 회색 삼각형 방지). 이미지 크기는 유지.
3. **90° 돌린 경우 여백 띠 정리**: 한 축 여백(최소값)이 다른 축 여백의 2배 초과면 그 축만 글자 영역+여백으로 자름(세로 문서가 가로로 바뀌는 문제 방지). 잘라서 넓이 85% 이상 남으면 하지 않음.
4. (선택) 선명하게: 흑백·대비 1.3.
5. 축소할 때 **정수 픽셀 크기**로(소수면 끝 열이 투명과 섞여 어두워짐), 가장자리 확장 후 Lanczos.

### 3.3 책 모드 (`BookProcessor`)
순서가 중요: **조명 고르게 → 쪽별 수평 → 테두리 정리 → 휜 줄 펴기(최대 2번) → 마무리 테두리 정리**
- 양쪽 분리: 가로로 긴 사진(가로 > 세로×1.05)에서 가로 30~70% 구간의 **글자가 없는 세로 띠** 중 가운데에 가장 가까운 것, 그 안에서 가장 어두운 열(접힌 곳 그림자)을 기준으로 자름. 양쪽 모두 글줄 3개 이상일 때만.
- 조명 고르게: 1/4로 줄여 밝은 값 확장(반경 = 긴 변/90/4) → 가우시안 흐림(반경 = 긴 변/90/3) = 종이 밝기 지도 → 원본 ÷ 지도.
- 테두리 정리: 회색조 900px, 종이 밝기−45보다 어두운 픽셀의 연결 덩어리 중 **가장자리에 닿은 것은 버림**(배경·책 단면·그림자·손가락). 남은 내용 상자에서 **빈 종이(종이 밝기−30 이상인 비율 90% 초과)가 이어지는 데까지 넓힘** → 쪽 모양(세로) 유지. 1% 안쪽으로, 글자 둘레 최소 3%.
- 휜 줄 펴기: 글줄마다 2글자 폭 구간으로 나눠 **글자 덩어리 윗선(8%)·아랫선(92%) 가운데** 높이를 잼(무게중심은 한글 모양 때문에 흔들림). 줄 가운데 구간에서 시작해 옆 구간 높이를 따라가며 ±0.75줄높이 범위만 봄(이웃 줄 섞임 방지). 퍼짐이 1.4줄높이 넘으면 버림.
  - 모델: `y = r_i + B1(u) [+ v_i·B2(u)]` (u=가로 0~1, v=세로 −0.5~0.5), B1은 4차(측정 40개 미만이면 3차), B2는 글줄 10개 이상일 때 2차. 전체 측정값으로 최소제곱, 잔차 3×중앙절대편차 넘는 점 빼고 재근사.
  - 측정 범위 밖은 끝 기울기로 5%만 직선 연장. 이동량 상한 = 쪽 높이의 6%.
  - **편 뒤 다시 재서 휨이 20% 이상 줄었을 때만 적용**(안전장치). 휨 2px 이하면 손대지 않음.

### 3.4 검색 가능한 PDF (`SearchablePdf`)
- 쪽 그림은 JPEG(품질 0.82)로 넣고, 그 위에 **보이지 않는 글자**(PDF 글자 그리기 방식 Tr=3)를 줄 상자에 맞춰 가로·세로로 늘려 씀. 글꼴: 맑은 고딕.
  - PDFsharp: `XGraphics`로 이미지 → 글자는 `XTextFormatter` 대신 **콘텐츠 스트림에 직접 `3 Tr`** 를 써야 투명 글자가 됨(PDFsharp 확장 필요). 검색·복사가 되는지 반드시 시험.
- **쪽 크기 통일**: 이미지를 정해진 쪽 크기 안에 비율 유지해 가운데 배치, 남는 곳은 이미지 테두리 색으로 채움. 내용이 가로면 같은 크기의 가로 쪽.
  - 자동: 스캔은 모든 이미지 비율(긴 변/짧은 변)의 **중앙값**으로 긴 변 841.9pt, PDF OCR은 원본 쪽 크기(책 모드로 나뉘면 가로를 나눈 수만큼).
  - A4 595.3×841.9 / B5 515.9×728.5 / Letter 612×792 pt.
- 줄 상자는 쪽 기준 좌표로 바꿔 보관(교정 화면에서 사용).

### 3.5 PDF 글자층 판별 (`PdfTextProbe`)
쪽 콘텐츠 스트림의 글자 그리기 명령(Tj, TJ, ', ")을 세고, 그때의 Tr 값(q/Q로 저장·복원)이 3이면 OCR 글자층.
→ **글자 없음 / OCR 글자층만 / 진짜 글자**. 이미 진짜 글자가 있는 쪽은 OCR·용량 줄이기·교정에서 건드리지 않음.
(Mac에서는 화면에 띄운 PDF에 OS가 자동 OCR을 붙여 `page.string`이 차는 문제가 있었음 — 파일 안의 명령으로만 판단할 것)

### 3.6 대용량·속도
- 동시 처리 쪽수 = `min(4, 코어수/2, (전체 메모리×15%) / (0.25GB×(dpi/300)²))`, 최소 1.
- 중간 결과(쪽별 PDF·보정 이미지)는 **디스크 임시 폴더**에 두고 메모리에는 미리보기만 → Mac 실측 300쪽 0.91GB, 12쪽 0.82GB(쪽수와 무관).
- 결과는 원래 순서대로 조립. 앱 종료 시 임시 폴더 삭제.

### 3.7 그 밖의 기능
- **폴더 자동 OCR**: 폴더 변경 감시 + 2.5초마다 확인, 파일 크기가 두 번 연속 같으면(다 쓰임) 처리. 결과 `OCR 완료/`, 원본 `처리한 원본/`, 실패 `OCR 실패/`(같은 파일 반복 시도 방지). 같은 이름이면 `이름 (2).pdf`.
- **교정**: 쪽 그림을 300dpi로 다시 그려(주석은 숨기고) 고친 글자층으로 쪽을 새로 만들어 교체, 주석은 옮겨 붙임. 여러 쪽을 되돌리기 한 번으로.
- **용량 줄이기**: 보통(이미지 화면용·JPEG, 진짜 글자 유지) / 작게(110dpi, 품질 0.6) / 아주 작게(90dpi 흑백, 품질 0.5). 진짜 글자 쪽은 그대로. 저장 전에 "원래 → 줄인 뒤 (n% 줄어듦)" 표시.
- **암호**: 열 때 암호 묻기(5번까지), 저장 시 같은 암호 유지, 설정·해제 메뉴. 작업용 임시 파일은 잠금 없는 사본.
- **탭**: 탭(=문서)마다 상태 따로, 탭 닫을 때 저장 확인, 이미 열린 문서는 그 탭으로.
- **주석**: 형광펜(기본 노랑)·밑줄·취소선·메모·글상자·펜·사각형·원·화살표·지우개·서명(한 번 그려 저장), 모두 되돌리기. PDF 표준 주석으로 저장.

## 4. 단계별 작업 계획

| 단계 | 내용 | 완료 기준 |

| 1 | 솔루션·프로젝트 만들기, PDF 열기·보기·썸네일·확대·검색 | PDF가 열리고 쪽 이동·검색 됨 |

- 설치 파일: Inno Setup으로 `한글스캔PDF_설치.exe` (자체 포함 .NET 런타임 → 받는 사람이 .NET 설치 불필요).
- **서명하지 않으면** 처음 실행 때 "Windows의 PC 보호" 경고 → "추가 정보 → 실행". 경고 없애려면 코드 서명 인증서 필요.
- GitHub Releases에 올려 링크로 공유.
- 필요 조건 안내: Windows 10(2004) 이상, 한국어 OCR 언어 팩.
